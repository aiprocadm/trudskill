# Инструкции для агентов (LMS trudskill)

Репозиторий рассчитан на работу **нескольких агентов** подряд. Единый регламент передачи и трактовки фразы **«продолжай по ТЗ»** зафиксирован здесь:

- **[docs/DOCUMENTATION_MAP.md](docs/DOCUMENTATION_MAP.md#agent-handoff-protocol)** — порядок чтения документов, что обновлять после сессии, иерархия при противоречиях.

Краткий порядок: `README.md` (блок **AI Agent State**) → `LMS_AGENT_HANDOFF.md` → **статус-трекер нужного ТЗ** → `TZ_TRUDSKILL_BASE.md` → `docs/TZ_MVP_TRACEABILITY.md`.

## «Продолжай по ТЗ» без уточнения = ТЗ перехода с CDOPROF

Действующих ТЗ четыре, но очередь работ — только в одном (с 23.09.2026). Вопрос «какой из них продолжать» владельцу не задаётся.

| Вопрос, на который отвечает документ                                                   | ТЗ                                                                     | Трекер                                                                                         |
| -------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| **Что делать дальше** — переход с CDOPROF: паритет функций и перенос данных (фазы 0–8) | [TZ_TRUDSKILL_CDOPROF_MIGRATION.md](TZ_TRUDSKILL_CDOPROF_MIGRATION.md) | [docs/TZ_CDOPROF_MIGRATION_STATUS.md](docs/TZ_CDOPROF_MIGRATION_STATUS.md) ← **читать первым** |
| Стабильность, блокеры, UX (фазы 1–18); **решения Р1–Р19 действуют везде**              | [TZ_TRUDSKILL_STABILIZATION_UX.md](TZ_TRUDSKILL_STABILIZATION_UX.md)   | [docs/TZ_STABILIZATION_UX_STATUS.md](docs/TZ_STABILIZATION_UX_STATUS.md)                       |
| **Как это должно выглядеть** — экран, меню, компонент, цвет, тексты интерфейса         | [docs/TZ_UI_REDESIGN_TRUDSKILL.md](docs/TZ_UI_REDESIGN_TRUDSKILL.md)   | [docs/TZ_UI_REDESIGN_STATUS.md](docs/TZ_UI_REDESIGN_STATUS.md)                                 |
| **Как это должно себя вести** — ручка API, право, миграция, очередь, документ          | [TZ_TRUDSKILL_ARENDNAYA_SDO.md](TZ_TRUDSKILL_ARENDNAYA_SDO.md)         | [docs/TZ_ARENDNAYA_SDO_STATUS.md](docs/TZ_ARENDNAYA_SDO_STATUS.md)                             |

Очереди трёх нижних ТЗ закрыты — они остаются **каноном по своему предмету**, а не очередью задач.

**Автономия по ТЗ перехода (поручение владельца 23.09.2026):** развилки агент решает сам и записывает строкой `РМ-N`, план фазы считается утверждённым в момент записи, позиции, ждущие данных или действий владельца (🚫), пропускаются, закрыв позицию — агент берёт следующую. Подробно — раздел «Правила автономии» в трекере.

**Если незакрытых задач нет нигде и журнал расхождений пуст** — сессия идёт в [режим ревизии](docs/AUDIT_MODE.md): берётся непройденный класс сверки и ищутся дефекты кода. Не спрашивать «чем заняться». Полное правило маршрутизации: [DOCUMENTATION_MAP.md#tz-routing](docs/DOCUMENTATION_MAP.md#tz-routing).

## Сверка логики с ТЗ — обязанность, а не инициатива

Любая работа по коду включает сверку затронутого участка с ТЗ. Что делать с найденным расхождением — в [`CLAUDE.md` § «Сверка логики с ТЗ»](CLAUDE.md). Коротко: **нашёл — записал в журнал расхождений**, чинить в этой же сессии только если это в рамках задачи и не ломает границы ТЗ.

Правило Cursor с тем же смыслом: `.cursor/rules/lms-multi-agent-handoff.mdc` (если файл присутствует в рабочей копии).
