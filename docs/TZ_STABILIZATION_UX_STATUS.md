## Правила ведения

1. Обновляется **в конце каждой сессии**, работавшей по этому ТЗ, — вместе с handoff `§5.XX` и README `§2` ([протокол передачи](./DOCUMENTATION_MAP.md#agent-handoff-protocol)).
2. Статусы: **✅ готово** (критерий приёмки ТЗ выполнен и проверен) · **🔄 в работе** · **🟡 частично** · **🔎 требует сверки** (код по теме есть, но соответствие критерию ТЗ не проверялось — типичный статус после ревью стенда) · **⬜ не начато** · **♻️ переделать**.
3. Текст требований сюда **не копировать** — только ID, статус, короткий указатель на код/handoff. Канон текста — само ТЗ.
4. Фаза стартует только после **плана в `docs/superpowers/plans/` и апрува владельца**. Фаза = один PR = один обратимый шаг, ≤30 файлов, зелёный `pnpm ci:check`.
5. Решения Р1–Р19 **не переоткрываются**. Если решение невыполнимо — описать конкретное препятствие и предложить замену, а не спрашивать «как вы хотите».
6. Расхождения «код ↔ ТЗ», найденные попутно, пишутся в **журнал расхождений** [TZ_UI_REDESIGN_STATUS.md](./TZ_UI_REDESIGN_STATUS.md) — журнал в репозитории **один**, второй не заводится. Если расхождение тянет на требование этого ТЗ — продублировать строкой сюда, в столбец «Указатель».
