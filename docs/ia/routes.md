# Реестр разделов: адрес → одно название → одна группа → роли

Требование ТЗ «Стабилизация, UX и развитие» **3.4 (Н3)**, пункт 1: «На основе аудита (0.1) составить реестр разделов: адрес → одно название → одна группа → роли».

## Зачем этот файл

Один и тот же раздел назывался по-разному в зависимости от того, откуда на него смотреть: `/notifications` — «Сообщения» в меню, «Уведомления» в шапке, «Центр уведомлений» в заголовке; настройки центра жили в четырёх пунктах; «Аудит» в меню открывал «Журнал действий». Аудит 0.1 насчитал 25 пунктов меню из 61, у которых заголовок страницы звучит иначе. Человек, ищущий «журнал», не находит его среди «аудитов».

**Правило:** у раздела ровно одно имя, и оно одинаково в меню, в заголовке страницы, в хлебных крошках, в результатах поиска и в разделах настроек.

## Где живёт истина

**Источник — код, а не этот файл.** Имя раздела объявлено в [`apps/frontend/src/features/navigation/model.ts`](../../apps/frontend/src/features/navigation/model.ts) (`navigationModel`: адрес → имя), блок — в [`nav-groups.ts`](../../apps/frontend/src/features/navigation/nav-groups.ts), доступ — там же в `routeMeta`. Роли в столбце «Кому открыт» посчитаны по снимку прав **живой базы** ([`role-permissions.fixture.ts`](../../apps/frontend/src/e2e/role-permissions.fixture.ts)): роль попадает в список, если у неё есть все права, которых требует адрес.

Документ пересказывает код словами. Чтобы пересказ не устарел молча, сторож [`one-section-one-name.e2e.test.ts`](../../apps/frontend/src/e2e/one-section-one-name.e2e.test.ts) сверяет с этим файлом каждый адрес и его имя — и заодно держит само правило: заголовок страницы равен пункту меню, словарь крошек не спорит с меню, разделы настроек называют экраны так же, ни одно имя не ведёт на два адреса.

## Хлебные крошки

Требование ТЗ **3.5 (Н5)**: последний элемент — название объекта с сервера (со скелетоном на время загрузки); идентификаторов, слагов и служебных сегментов в крошках нет; у слушателя своя иерархия.

**Правило:** `Блок → Раздел → Имя объекта`.

- **Блок** — подпись без ссылки, из `NAV_GROUPS` (`resolveGroupForPath`). Внутри кабинета слушателя (`/learner` и всё под ним) блока нет: там иерархия начинается с «Мой кабинет».
- **Раздел** — только сегмент, за которым есть страница: пункт меню (имя из `navigationModel`) или страница без пункта меню (имя из `pageLabels`, см. ниже). Служебные слова адреса (`admin`, `attempt`, `platform`, `esign`, `submit`, `result`) пропускаются.
- **Имя объекта** — все идентификаторы адреса сворачиваются в одну крошку; имя публикует экран карточки через `useObjectCrumb(имя, { notFound, failed })`. Пока имени нет — скелетон; объекта нет — «Не найдено»; не загрузился — «Не удалось загрузить».
- **«Главной» нет:** `/` — диспетчер входа (служебный адрес по 3.4), а для слушателя он вёл в «Мой кабинет» — получалось два имени одного места подряд.

Сторож — [`breadcrumbs-name-the-object.e2e.test.ts`](../../apps/frontend/src/e2e/breadcrumbs-name-the-object.e2e.test.ts): обходит **реальное дерево `app/`** и проверяет, что у каждой страницы оболочки есть своя крошка, ни одна подпись не сырой сегмент, каждый экран карточки называет объект, а подпись страницы без пункта меню равна её заголовку.

### Страницы без пункта меню

Единственные адреса, чьё имя крошки берут не из меню. Имя равно заголовку страницы (сторож сверяет).

| Адрес           | Название                  |
| --------------- | ------------------------- |
| `/courses/new`  | Создание курса            |
| `/groups/new`   | Новая группа              |
| `/crm/deals`    | Сделки                    |
| `/forms`        | Системные формы           |
| `/mailings`     | Рассылки и уведомления    |
| `/module-empty` | Раздел в разработке       |
| `/admin/ui-kit` | Витрина шаблонов (UI Kit) |

До 3.5 словарь был привязан к слову-сегменту, а не к адресу: `new` называлось «Создание» и для курса, и для группы, а сегменты без своей страницы (`esign`, `crm`, `learning`, `platform`) получали подпись и становились ссылкой в никуда.

## Что этот файл НЕ решает

- **Заголовок вкладки браузера** (`<title>`): его нет ни у одной страницы (журнал 394). Прогонять реестр по нему пока не по чему — это задача 4.3.
- **Заголовок карточки** (`<h1>` объекта): по TPL-002 это имя объекта, как и последняя крошка; сверка заголовков карточек с крошками — задача 4.3.
