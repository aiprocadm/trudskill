# Единые правила экранов

Требование ТЗ «Стабилизация, UX и развитие», **фаза 5**: «каждое правило оформляется как компонент/утилита в `@trudskill/ui` + запись в `docs/ui/patterns.md`, а затем раскатывается по экранам». Здесь — по одной записи на правило: что оно значит для человека, каким компонентом держится, какой сторож не даст его нарушить. Канон формы — [ТЗ редизайна](../TZ_UI_REDESIGN_TRUDSKILL.md) (`CMP-*`, `TPL-*`); тексты — [`tone-of-voice.md`](./tone-of-voice.md).

## Э1 · Один набор действий в строке таблицы

**Для человека.** В строке реестра стоит одно основное действие — обычно «Открыть». Всё остальное — в меню «…». Опасные действия («Приостановить центр», «Архивировать») — в этом меню внизу, отдельной секцией, красным: до них нельзя дотянуться случайно, целясь в соседний пункт. Четыре подчёркнутые ссылки подряд — так больше не бывает.

**В коде.** `DataTable` принимает `rowActions={(row) => RowAction[]}`; раскладку делает `splitRowActions` (`packages/ui/src/components/table/row-actions.ts`), меню рисует `OverflowMenu` (`packages/ui/src/components/overflow-menu/`). Экран лишь помечает основное действие:

```ts
rowActions={(row) => [
  { label: 'Открыть группу', primary: true, onSelect: () => open(row) },
  { label: 'Сменить тариф', onSelect: () => changePlan(row) },
  { label: 'Закрыть группу', danger: true, onSelect: () => close(row) }
]}
```

- `primary` — не больше одного; опасное действие основным быть не может.
- Единственное неопасное действие показывается сразу: меню из одного пункта — лишний клик.
- Единственное опасное действие — только через меню.
- На телефоне (≤480px) меню «…» — кнопка внизу карточки во всю строку (`CMP-001`).

**Не так.** Своя колонка `{ title: 'Действия', render: (row) => <button…> }` — кнопки мимо правила. Такие таблицы стоят в очереди сторожа и переводятся на `rowActions` в 5.6 (единый шаблон списка).

**Сторож.** `apps/frontend/src/e2e/one-action-set-per-row.e2e.test.ts`: таблица пакета раскладывает действия по правилу; опасные — внизу за разделителем; на экране не больше одного `primary`; очередь своих колонок «Действия» не растёт.

## Э2 · Действие соответствует состоянию объекта

**Для человека.** Кнопка говорит, что можно сделать с объектом _сейчас_: у черновика курса — «Опубликовать курс», у опубликованного — «Создать новую версию», у архивного — ничего. Начатая попытка теста — «Продолжить» и подпись «Попытка начата и не завершена», а не «Осталось попыток: 0 из 1». Действие, которое человеку недоступно (нет права) или невозможно (не то состояние), не показывается вовсе — ни серым, ни «вхолостую». Одно исключение: черновик без структуры — кнопка выключена, а рядом список того, чего не хватает: человеку нужно знать, что сделать.

**В коде.** Выбор действия — чистая функция по состоянию, а не набор `if` в разметке: `courseHeaderAction` (`features/courses/course-actions.ts`), `attemptsCaption` (`features/test-player/format.ts`). `DataTable` рисует колонку «Действия», только если хоть у одной строки они есть. Предложение «Создать первый шаблон» и кнопка «Создать шаблон» — только с правом `documents.write`.

**Сервер — источник правды.** Возможность действия проверяет ручка, кнопка лишь отражает её правила: `publishCourse` отвечает `409 course_not_draft` опубликованному и архивному курсу, `archiveCourse` — `409 course_already_archived`, `startAttempt` — `attempt_limit_reached`. Экран, который покажет кнопку не по состоянию, получит отказ с человеческим текстом, а не молчаливое «ничего не произошло».

**Не так.** `primaryAction={{ label: 'Опубликовать курс', disabled: !ready }}` без взгляда на `status`; `rowActions={() => []}` с пустой колонкой; кнопка «создать» на пустом экране без права.

**Сторож.** `apps/frontend/src/e2e/action-matches-state.e2e.test.ts`: карточка курса берёт действие из `courseHeaderAction`; таблица прячет пустую колонку; список тестов подписывает попытки по состоянию; шаблоны и их создание — за правом; сервер отказывает повторной публикации и повторному архиву.

## Э3 · Подтверждение необратимых действий

**Для человека.** Перед тем, что нельзя отменить, система переспрашивает — и переспрашивает по делу: называет объект («Закрыть группу «Группа 360px»?»), называет последствие («слушателям будут выпущены документы, состав группы изменить будет нельзя») и требует осознанного клика. Самое тяжёлое — закрыть группу, перевести центр в архив, отозвать лицензию — требует ввести название или номер того, с чем работаешь: так подтверждается и намерение, и что выбрана та самая запись. Не слово-заклинание («УДАЛИТЬ»), а признак записи.

**В коде.** Диалог — только из пакета: `useConfirmDialog().ask(request, action)` или `ConfirmDialog` (`CMP-005`, `CMP-006`); браузерные `confirm()`/`prompt()` запрещены. Запрос собирает чистая функция рядом с экраном (`statusChangeRequest`, `closeGroupRequest`, `finishTestRequest`) — её значения проверяются тестом, экран лишь зовёт `ask`. Поля: `title` с объектом, `message` с последствием, `confirmLabel` — результат действия (тот же текст, что на кнопке и в реестре), `tone: 'danger'` для необратимого, `requireTyping: { word, label, hint }` для самого тяжёлого.

**Где что.** Приостановить центр — диалог, опасный тон; перевести центр в архив — ввод кода центра; отозвать лицензию — ввод номера; закрыть группу (одиночно и цепочкой) — ввод названия группы; закрыть выбранные группы — диалог с числом (названий много, отказы покажем поимённо); архивировать слушателей — диалог с числом и последствием; завершить тест по кнопке — диалог с числом вопросов без ответа, без ввода (на экзамене печатать название — издевательство); автосдача по таймеру — без диалога, выбора там уже нет.

**Не так.** Кнопка опасного действия с одного нажатия; диалог «Вы уверены?» без объекта; `tone: 'danger'` без последствия в тексте.

**Сторожа.** `irreversible-confirms-object.e2e.test.ts` (шесть действий ТЗ на месте; каждый опасный диалог называет объект и последствие), `irreversible-needs-typing.e2e.test.ts` (текст «нельзя отменить» без ввода — дефект), `browser-dialogs-ban.e2e.test.ts`, `dialogs-come-from-package.e2e.test.ts`.

## Э4 · Опасное действие — не главная кнопка экрана

**Для человека.** Самая яркая кнопка экрана всегда предлагает сделать дело, а не разрушить его. В карточке группы это «Зачислить слушателя», а не «Закрыть группу»: закрытие никуда не делось — оно стоит рядом вторичным, красным, под тем же подтверждением с вводом названия. Глаз ведёт к работе, а не к необратимому.

**В коде.** `PageHeader` принимает `primaryAction?: SafePageAction` — это `PageAction`, у которого `danger` обязан отсутствовать или быть `false`. Опасное действие туда не попадёт: `danger: true` и даже вычисленное `danger: isDanger` (тип `boolean`) компилятор отвергает. Вторичные — `secondaryActions?: PageAction[]`, там `danger: true` разрешён: такая кнопка рисуется красной, а в меню «Ещё» опасные пункты уходят вниз. Порядок и цвет считает компонент, а не каждый вызывающий — правило, которое обязан помнить каждый, соблюсти нельзя (урок Э1).

```tsx
<PageHeader
  title={group.name}
  {...(canEnroll ? { primaryAction: { label: 'Зачислить слушателя', onSelect: openEnroll } } : {})}
  secondaryActions={[
    ...(canWriteDocuments ? [{ label: 'Сгенерировать приказ', onSelect: openOrder }] : []),
    ...(canGenerateDocuments
      ? [{ label: 'Закрыть группу', danger: true, onSelect: openClose }]
      : [])
  ]}
/>
```

**Акцент — не только у шапки.** Голая `className="ui-button ui-button--primary"` внутри панели или секции — тоже главная кнопка того, что человек видит. В панели закрытия группы оранжевой была «Запустить цепочку»: подпись нейтральная, а действие — тот же необратимый выпуск документов с номерами и строк госвыгрузки. Акцент снят; в панели акцентной кнопки нет вовсе.

**Что не нарушение.** Кнопка внутри `ConfirmDialog` — человек уже осознанно её вызвал. Экран экзамена: «Завершить тест» необратимо, но сдать работу — и есть конструктивная цель экрана, другого действия там нет (в Э3 подтверждение завершения намеренно собрано без `tone: 'danger'`). Панель, открытая ради одного опасного действия (аннулирование документа), сохраняет свою кнопку — но красной, а не в конструктивном оранжевом.

**Не так.** `primaryAction: { label: 'Закрыть группу' }`; оранжевая кнопка у самой тяжёлой операции панели, когда соседняя, более узкая, выглядит скромнее.

**Сторож.** `apps/frontend/src/e2e/danger-is-not-primary.e2e.test.ts` смотрит на **два** признака, потому что одного не хватает: **подпись** (узкий словарь однозначных корней: «закрыть групп», «удал», «архивиров», «отозв», «аннулир», «обезлич», …) и **намерение** (действие идёт через подтверждение с `tone: 'danger'` — метка, поставленная в Э3). «Закрыть группу» ловится подписью, «Запустить цепочку» — только намерением. Спорные слова («отмен», «заверш», «отклон») в словарь не взяты намеренно: широкий словарь покраснел бы на кнопке «Отмена» в подвале каждой панели, его начали бы глушить исключениями, и он умер бы.

## Э5 · Панель массовых действий — липкая

**Для человека.** Выделил строки — панель появилась внизу экрана и оттуда никуда не девается, сколько ни листай. Она говорит, сколько строк выбрано, и предлагает то, ради чего люди и выделяют пачку: добавить в группу, выгрузить, а уже потом — архивировать. Красное действие стоит последним, чтобы в него не попасть, целясь в соседнее.

**В коде.** Панель — `BulkActionBar` из пакета: `selectedCount`, `actions`, `onClear`, `isRunning`, `outcome`. Компонент сам возвращает два узла: саму панель (`position: fixed`, низ окна) и распорку `.ui-bulk-bar-spacer`, которая оставляет под неё место в потоке. Порядок действий тоже считает компонент — `danger` печатается последним.

```tsx
<BulkActionBar
  selectedCount={selected.length}
  isRunning={enroll.isRunning}
  {...(outcome ? { outcome } : {})}
  actions={[
    ...(canEnroll ? [{ label: 'Добавить в группу', onSelect: openEnroll }] : []),
    { label: 'Выгрузить выбранных', onSelect: exportSelected },
    { label: 'Архивировать', danger: true, onSelect: confirmArchive }
  ]}
  onClear={() => setSelected([])}
/>
```

**Почему не `sticky`.** Так и было записано — `position: sticky; bottom: 0` — и не работало ни разу: панель идёт последним элементом страницы, а прилипание снизу у последнего ребёнка не даёт ничего, двигаться ему некуда. Панель оказывалась ниже пагинации. Теперь `fixed`, а слева отступ на ширину колонки меню — переменная `--ui-shell-nav`, та же, что задаёт саму колонку (260px, 64px у свёрнутой, 0 на телефоне). Числом эту ширину не писать: панель разъедется с меню при первой же правке.

**Сколько действий.** Больше одного, и хотя бы одно не опасное — причём показанное ВСЕГДА, а не за правом. Действие под правом (`...(можно ? [ … ] : [])`) у другой роли исчезает, и в панели снова остаётся одно красное «Архивировать»: поэтому «Выгрузить выбранных» доступно всем, кто видит сам реестр. Выделение ради одного красного действия — не работа со списком. Итог операции показывается в той же панели поимённо: «12 из 15, не прошли: Иванов И. И. — нет СНИЛС».

**Сторож.** `apps/frontend/src/e2e/bulk-bar-is-sticky.e2e.test.ts`: панель `fixed` и отступает по `--ui-shell-nav`; распорка есть; ширина колонки — одна переменная на три состояния; порядок и счётчик считает компонент; у каждой панели ≥2 действий и ≥1 неопасное БЕЗУСЛОВНОЕ (список разбирается на элементы, спред под условием не засчитывается).

## Э6 · Один шаблон списка для всех списков

**Для человека.** Любой список в системе устроен одинаково: сверху быстрые отборы, под ними строка поиска и фильтры, справа в той же строке — выбор колонок, дальше таблица, под ней страницы, а внизу, когда что-то выделено, — панель массовых действий. Научился работать с «Слушателями» — умеешь работать с «Группами», «Курсами», «Людьми и доступом». Не нужно каждый раз искать, где на этом экране спрятан поиск.

**В коде.** Блоки приходят каркасу `ListPage` (`packages/ui/src/composition/list-page.tsx`) **слотами**, а порядок печати задаётся внутри каркаса и нигде больше:

```tsx
<ListPage<LearnerListItem>
  savedViews={<SavedViews … />}
  filters={
    <>
      <SearchInput … />
      <select aria-label="Статус">…</select>
    </>
  }
  secondaryFilters={…}
  activeFilterCount={activeFilters}
  onResetFilters={…}
  columnPicker={<ColumnPicker … />}
  columns={columns}
  rows={rows}
  isLoading={list.isLoading}
  page={page}
  totalPages={totalPages}
  onPageChange={setPage}
  bulkBar={<BulkActionBar … />}
/>
```

Раньше каждый из этих блоков экран рисовал сам и ставил **рядом** с каркасом. Порядок держался только тем, что автор написал их в нужном порядке, — то есть правилом, которое обязан помнить каждый. Такое правило соблюсти нельзя (урок Э1 и Э5), поэтому его считает компонент.

**Пагинация исчезает, когда страница одна.** «Назад 1 / 1 Вперёд» под списком из одной строки не сообщает ничего, но выглядит как элемент управления: человек жмёт и ничего не происходит.

**Колонки соответствуют доступным фильтрам.** Отбор по роли — значит, в таблице есть колонка «Роль». Отбирать по признаку, которого на экране не видно, — значит просить человека верить, что фильтр сработал. В «Людях и доступе» отбор по роли был, а колонки не было; вместе с колонкой роли появились и в ответе сервера (`GET /users` отдаёт коды ролей строк ТЕКУЩЕЙ страницы, одним запросом).

**Эталон — «Слушатели».** Быстрые отборы с тремя готовыми, поиск, отбор по статусу, выбор колонок, галочки, массовые действия. Остальные списки приводятся к нему, а не наоборот.

**Не так.** `<FilterBar>` отдельным блоком над `<ListPage>`; своя колонка «Действия» с кнопками внутри ячейки (см. Э1); панель отбора, в которую вместо фильтров положили форму создания записи.

**Сторож.** `apps/frontend/src/e2e/one-list-template.e2e.test.ts`: порядок блоков считает каркас; пагинация уходит при одной странице; ни один экран не рисует блоки списка рядом с каркасом (очередь исключений — с причиной у каждой записи); «Группы» ищут и отбирают НА СЕРВЕРЕ; у отбора по роли есть колонка «Роль», а у колонки — данные из ручки.

## Э7 · Разбить «простыни»

**Для человека.** «Простыня» — страница, где в одну ленту свалено 4–6 несвязанных блоков. Чтобы понять, что на ней вообще есть, её прокручивают целиком; чтобы вернуться к нужному месту — прокручивают снова. Теперь состав страницы виден одной строкой вкладок, и открыт ровно один раздел. Ссылку на нужный раздел можно передать коллеге: открытая вкладка стоит в адресе.

**Где это было.** Четыре страницы, названные ТЗ поимённо:

| Страница             | Было одной лентой                                                        | Стало вкладками                                                            |
| -------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------------- |
| Арендаторы платформы | реестр + здоровье + тарифы + счета + форма создания центра посреди всего | Учебные центры · Здоровье платформы · Тарифы · Счета аренды                |
| Документы            | бланки + задачи выпуска + нумераторы + подпись и печать                  | Бланки · Задачи выпуска · Нумерация · Подпись и печать                     |
| Настройки            | оглавление слева, справа семь разделов подряд                            | оглавление переключает вкладки; открыт один раздел                         |
| Карточка курса       | версии + параметры + документы + модули + материалы                      | Состав программы · Нормативные параметры · Документы по окончании · Версии |

**В коде.** Полоса — `PageTabs`, содержимое — `TabPanel`, оба из `@trudskill/ui`. Адрес ведёт хук `useTabParam` (`features/navigation/use-tab-param.ts`), чистые функции разбора — `tab-param.ts`.

```tsx
const [tab, setTab] = useTabParam(COURSE_TABS.map((item) => item.id));

<PageTabs tabs={COURSE_TABS} activeId={tab} onSelect={setTab} label="Разделы карточки курса" />
<TabPanel id="content" activeId={tab}>…</TabPanel>
<TabPanel id="params" activeId={tab}>…</TabPanel>
```

- **Один уровень.** Вложенные вкладки запрещены (`TPL-002`, §7.2): второй уровень превращает навигацию в лабиринт — человек перестаёт понимать, где он и что откроется по кнопке «назад».
- **Закрытая вкладка не рисуется вовсе**, а не прячется стилем: спрятанное стилем находится поиском по странице (Ctrl+F) и грузит данные впустую.
- **`replace`, а не `push`.** Переключение вкладок — осмотр одной страницы, а не переходы: иначе кнопка «назад» после четырёх вкладок нажимается четыре раза.
- **Незнакомая вкладка возвращает к первой.** Опечатка в чужой ссылке не должна наказывать того, кто по ней пришёл.
- **Отбор сохраняется.** `?tab=` дописывается к остальным параметрам, а не заменяет их.

**Формы создания — в панели, а не внизу ленты.** «Новый арендатор» стоял блоком ниже тарифов и счетов: чтобы завести центр, страницу прокручивали до конца. Теперь это первичное действие шапки, открывающее `DetailDrawer` с предупреждением о несохранённом (`CMP-005`).

**Что остаётся вне вкладок.** Подсказка «что мешает опубликовать курс» стоит НАД вкладками и видна всегда: она объясняет, почему первичная кнопка выключена. Спрятать её во вкладку значит оставить человека с неработающей кнопкой без объяснения.

**Честные вкладки в «Настройках».** Оглавление разделено на две группы с разными заголовками: **«Настроить здесь»** — кнопки, меняют содержимое справа и ничего больше; **«Открыть отдельный раздел»** — ссылки, уводят на свою страницу. Раньше по виду они были неотличимы. Старые ссылки с якорем (`/settings#payments`) продолжают работать: якорь при заходе переводится в `?tab=`.

**Не так.** Второй уровень вкладок; вкладка, которой нет в адресе; форма создания блоком в конце ленты; строка оглавления, по виду неотличимая от ссылки на другую страницу.
