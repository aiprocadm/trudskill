Это не останавливает работу: весь код импорта и сверки строится на **обезличенных синтетических фикстурах** по описанию API и колонкам выгрузок; живой прогон — отдельная строка со статусом 🚫 (см. «Правила автономии», п. 4).

## Правила автономии (поручение владельца от 23.09.2026)

Владелец поручил: **вопросы, требующие его решения, агент решает сам, выбирая наиболее эффективный вариант; фраза «продолжай по ТЗ» должна доделывать проект.** Отсюда:

1. **Владельцу вопросов не задавать.** При развилке выбрать вариант по приоритетам сверху вниз: (1) сохранность данных и изоляция тенантов → (2) совместимость: не ломать контракты `packages/api-contracts`, URL и существующие права — только добавлять → (3) обратимость (флаг, аддитивная миграция, редирект) → (4) меньший объём при той же пользе → (5) рекомендация самого ТЗ. Решение записать строкой в «Журнал решений агента» (`РМ15`, `РМ16`, …) с причиной — одной строкой.
2. **План фазы — обязателен, апрув — делегирован.** План пишется в `docs/superpowers/plans/YYYY-MM-DD-cdoprof-migration-phase-<N>-<slug>.md` и считается утверждённым в момент записи; паузы на апрув нет. Правило CLAUDE.md «план + апрув владельца» для этого ТЗ выполняется этим поручением.
3. **Этим ТЗ уже разрешены** (решение владельца в смысле CLAUDE.md «Границы»): новые роли `curator` и `viewer` и новые права из §12; новые ручки из §16 и новые **необязательные** поля в контрактах; новые маршруты `/tasks`, `/calendar`, `/curator`, `/settings/import-cdoprof` и редирект `/learning/calendar → /calendar?types=deadline`; новые схемы и таблицы §17. **Не разрешено и по-прежнему запрещено:** удалять/переименовывать существующие поля контрактов, менять смысл существующих прав, править исторические миграции, ослаблять сторожевые тесты.
4. **Внешние блокеры не останавливают очередь.** То, что физически может сделать только владелец (ключ API, выгрузки, продление подписки, провайдер почты, боевой стенд, приёмка сверки), получает статус **🚫 ждёт вход** и строку в разделе «Что нужно от владельца». Агент **сразу берёт следующую незаблокированную позицию**. Код для заблокированной части пишется заранее на синтетических фикстурах, чтобы по приходе входа оставался один запуск.
5. **Работать до конца сессии, а не до конца одной задачи.** Закрыл позицию (зелёный `pnpm ci:check`, PR, обновлён трекер) — бери следующую. Фаза = один или несколько PR, каждый ≤30 файлов, каждый — обратимый шаг.
6. **Необратимое — только владелец.** Финальная миграция на боевом контуре, заморозка ввода в CDOPROF, отключение CDOPROF, удаление данных, отправка писем реальным людям — агент готовит runbook и команды, но не выполняет.
7. **Решения РМ1–РМ14 не переоткрываются.** Если решение оказалось невыполнимым — описать препятствие и принять замену новой строкой журнала решений (не спрашивать).
8. **Сверка и журнал расхождений — как везде** (CLAUDE.md «Сверка логики с ТЗ»): найденное вне задачи — в журнал расхождений [TZ_UI_REDESIGN_STATUS.md](./TZ_UI_REDESIGN_STATUS.md), дефекты логики (изоляция, fail-open прав, потеря данных) — чинить сразу.
