# Источник CDOPROF: колонки, объёмы, известная грязь (Фаза 0, МГ-K1.1)

**Дата:** 2026-09-23. **ТЗ:** `TZ_TRUDSKILL_CDOPROF_MIGRATION.md` §13.1, §13.4. **План:** `docs/superpowers/plans/2026-09-23-cdoprof-migration-phase-0-audit.md`.

**Статус документа.** Всё, что здесь помечено ✔, взято из описания API (`cdoprof-openapi-v1.yaml`) и обследования ТЗ (Часть I). Всё, что помечено **?**, — вопросы живого прогона: у агента нет ключа API и выгрузок Excel (🚫 О1, О2 в трекере). Когда владелец даст ключ, живой прогон `pnpm export:cdoprof` на стенде закроет эти вопросы за один запуск — манифест выгрузки покажет реальные колонки и заполненность без единого ФИО в репозитории.

## 1. Что умеет API v1 ✔

Только чтение, `GET`, ключ в параметре `api_key`, ограничение по IP, страница ≤100 записей. Конверт списка: `{ success, data: { items[], pagination: { page, limit, total, pages, has_prev, has_next } } }`.

| Метод                           | Что отдаёт                                                                  | Параметры                                               | Объём (обследование 23.09) | Что берём (§13.2)                   |
| ------------------------------- | --------------------------------------------------------------------------- | ------------------------------------------------------- | -------------------------- | ----------------------------------- |
| `contragent.get`                | контрагенты                                                                 | `page, limit, search` (по названию, ИНН, почте)         | **1 622** (82 страницы)    | всё, ключ дедупликации ИНН+КПП      |
| `contragent.byInn`              | контрагент по ИНН                                                           | `inn` (10 или 12 цифр)                                  | —                          | проверка при ручном сопоставлении   |
| `contragent.students`           | слушатели контрагента                                                       | `contragent_id`, `student_id?`, `page, limit`           | —                          | связь слушатель → контрагент        |
| `student.get`                   | все слушатели                                                               | `page, limit, search, search_column`                    | **13 755** (688 страниц)   | всё, кроме пароля                   |
| `course.parent.get`             | направления                                                                 | `page, limit, search, search_column (id, name_course)`  | **18**                     | `learning.directions`               |
| `course.get`                    | курсы                                                                       | `search_column: id, id_parent_course, cod, name_course` | **~427**                   | `learning.courses` + версия 1       |
| `group.get`                     | группы                                                                      | `page, limit, search, search_column`                    | **24 756** (1 227 страниц) | `learning.groups`                   |
| `contragent.students.trainings` | обучения всех слушателей контрагента: слушатель × курс × группа × результат | `contragent_id`                                         | по вызову на контрагента   | зачисления, курсы групп, результаты |
| `contragent.report`             | файл отчёта по контрагенту (302 на файл)                                    | `inn, date_from, date_till`                             | —                          | не используем в импорте             |
| `report.endcert`                | «Окончания удостоверений» (302 на файл)                                     | `contragent_id?, date_from, date_till`                  | —                          | сверка сроков (Фаза 4, при наличии) |

Полная выгрузка — примерно **1 060 постраничных запросов + 1 622 вызова обучений**. При паузе 300 мс это около 15 минут чистого ожидания; лимиты частоты CDOPROF **?** неизвестны — транспорт держит паузу и повторяет 429/5xx с растущей задержкой.

## 2. Колонки по сущностям ✔

Типы — из OpenAPI; «nullable» там объявлено почти у всего, поэтому схемы клиента считают каждое поле необязательным, а профиль колонок в манифесте выгрузки покажет, что заполнено на самом деле.

### Контрагент (`Contragent`)

`id` int · `inn` · `name_organiztion` (опечатка источника — так и в API) · `short_name` · `post` · `city` · `addres` · `yur_addres` · `fact_addres` · `okpo` · `okato` · `oktmo` · `okogu` · `okopf` · `okvd` · `ogrn` · `kpp` · `email` (nullable) · `fio_directora` · `director_position` (nullable).

Чего нет: менеджера, даты договора, примечания, контактных лиц, телефона — это только из отчёта «Контрагенты с контактами» (Excel, **?** О2).

### Слушатель (`Student`)

`id` int · `id_organiz` int · `login` · `email` · `phone` · `full_name` · `surname` · `name` · `otchestvo` · `data_rozdeniya` · `sex` · `dolznost` · `created_at` — все строковые поля nullable.

Чего нет: СНИЛС, паспорта, адреса, гражданства, образования, диплома, доп. строк 1–10, согласия на ПДн, фото, файлов — только из «Выгрузки базы» / «Выгрузки списка слушателей» (Excel, **?** О2). Пароль в API не отдаётся и не переносится (§13.2).

**?** Формат `data_rozdeniya` и `created_at` (ISO `YYYY-MM-DD`, `DD.MM.YYYY`, с временем?) — фикстуры используют ISO как допущение; живой прогон покажет. **?** Значения `sex` («м»/«ж», «male»/«female», 1/2?).

### Направление (`ParenCourse`) и курс (`Course`)

Направление: `id` int · `name_course` (в названии — R-код и номер: `R13 1. Охрана труда …`).

Курс: `id` int · `id_parent_course` int · `cod` (`R13.Б`) · `name_course` · `count_hour` · `hours_theory` · `hours_practice` · `period_obuch` (**в месяцах**; у нас `period_days_default` — пересчёт в Фазе 4) · `date_add` · `price` · `note`.

Чего нет: настроек документов/ЕИСОТ/ФРДО курса, учебного плана, лекций, тестов — контент переносится отдельно (МГ-E2.4).

### Группа (`Group`)

`id` int · `name_group` · `date_create` · `date_on` · `date_off` · `access_material` · `date_exam_start` · `date_exam_end` · `date_practice_on` · `date_practice_off`.

Чего нет: статуса (в CDOPROF его и нет — только даты, ТЗ I.2 P7), курсов группы, состава, комментария, ответственного, формы обучения. Состав и курсы — только через `contragent.students.trainings` по каждому контрагенту; остальное — из «Журнала регистрации групп» (Excel, **?** О2).

### Обучения (`contragent.students.trainings`)

`{ contragent, items: [{ student, trainings: [{ course, group, result: { code, result, result_rus } }] }], pagination? }`.

**?** В OpenAPI `items` и `trainings` описаны как **объекты**, хотя по смыслу это списки. Клиент принимает обе формы и нормализует в массив. **?** Есть ли постраничность у этого метода (параметра `page` в описании нет, а `pagination` в ответе есть). **?** Полный словарь `result.code` / `result_rus` — в фикстурах `1 / Сдал`, `0 / Не сдал`, `2 / Неявка` как допущение; словарь нужен для правила «результат → статус зачисления» (§13.2).

## 3. Чего в API нет совсем ✔ (ТЗ I.1.10)

Номера и даты протоколов и удостоверений, серия-номер, разряд, состав групп напрямую, СНИЛС/паспорт/доп. поля, согласие на ПДн, сотрудники центра и их права, комиссия, задачи календаря, файлы, шаблоны документов, настройки нумерации, результаты по попыткам.

Источник для всего этого — отчёты Excel и настройки (§13.1). **Колонки Excel-выгрузок в этом документе не описаны: образцов нет (О2).** Когда появятся — сюда добавляется раздел на каждую выгрузку: название колонки → тип → поле TrudSkill → правило.

## 4. Известная грязь источника (ТЗ I.1.3, I.2 P8) ✔

Всё это вложено в обезличенные фикстуры `apps/backend/src/modules/import-cdoprof/__fixtures__/cdoprof-api/dataset.json`, чтобы импорт Фазы 4 учился на ней с первого теста:

| Что                                             | Где в источнике         | Что делает импорт (§13.2)                                                         |
| ----------------------------------------------- | ----------------------- | --------------------------------------------------------------------------------- |
| Дата рождения `2109-12-01`                      | слушатели               | даты вне `[1920; сегодня−14]` → пусто + строка отчёта                             |
| Дубли слушателей (одно ФИО+ДР, «ё»/«е»)         | слушатели               | дедупликация external_id → СНИЛС → ФИО+ДР с нормализацией; «кандидаты на слияние» |
| Только `full_name`, без фамилии/имени           | слушатели               | `parseFullName`                                                                   |
| Должность и комментарий — строка `undefined`    | слушатели, сотрудники   | считается пустым; манифест выгрузки считает такие строки отдельно                 |
| Почта «нет» и прочие не-адреса                  | слушатели               | невалидные → пусто + отчёт                                                        |
| Слушатель без контрагента (`id_organiz` null)   | слушатели               | физлицо                                                                           |
| Пустой ИНН; 12-значный ИНН (ИП/физлицо)         | контрагенты             | пустой → «требует реквизитов»; дедупликация ИНН+КПП                               |
| Название с пробелами по краям, дубли названий   | контрагенты             | trim + схлопывание пробелов; дубли — в отчёт                                      |
| Дубль номера группы                             | группы                  | код = `name_group`, при дубле `name_group-<id>`                                   |
| Группа без дат                                  | группы                  | статус «без документов»/по правилу дат; в отчёт                                   |
| Курс с несуществующим направлением              | курсы                   | направление «без направления» + отчёт                                             |
| Сотрудник «Менеджер» без ФИО, дубли сотрудников | пользователи (не в API) | не переносить; объединять вручную (23 человека)                                   |

## 5. Как снять живую выгрузку на стенде (когда будет ключ — О1)

```bash
# на стенде миграции, из корня репозитория
export CDOPROF_API_BASE_URL=https://<центр>.cdoprof.com   # адрес из «Настройка УЦ → API»
export CDOPROF_API_KEY=<ключ>                              # там же; IP стенда — в белом списке
export CDOPROF_EXPORT_DIR=/var/lib/trudskill/cdoprof-export # ВНЕ репозитория: в файлах ПДн
pnpm export:cdoprof                 # ~15–20 мин; --no-trainings — быстрая проверка без обучений
```

На выходе 7 файлов (`contragents.json`, `students.json`, `parent-courses.json`, `courses.json`, `groups.json`, `trainings.json`, `manifest.json`), папка `0700`, файлы `0600`. **В репозиторий и в чат кладётся только `manifest.json`** — там счётчики, длительность, профиль колонок (заполнено / пусто / строк «undefined») и поимённый список контрагентов, у которых не выгрузились обучения. Данных в нём нет.

Учебный прогон без ключа (проверить, что всё собрано): `pnpm export:cdoprof -- --fixtures`.
