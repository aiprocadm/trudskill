# Статус выполнения ТЗ по редизайну интерфейса

Трекер прогресса по [TZ_UI_REDESIGN_TRUDSKILL.md](./TZ_UI_REDESIGN_TRUDSKILL.md) (дельта-ТЗ **уровня представления**). Агент по фразе **«продолжай по ТЗ»** читает этот файл, чтобы понять: **какая фаза текущая, что сделано, что частично, что не начато и что нужно переделать**.

Это **второй** активный трекер репозитория. Первый — [TZ_ARENDNAYA_SDO_STATUS.md](./TZ_ARENDNAYA_SDO_STATUS.md) (поведение, функции, права). Какой из двух брать по фразе «продолжай по ТЗ» — решается по [правилу маршрутизации](./DOCUMENTATION_MAP.md#tz-routing); при сомнении **спросить владельца одним вопросом**, а не выбирать молча.

## Правила ведения

1. Обновляется **в конце каждой сессии**, работавшей по этому ТЗ, — вместе с handoff `§5.XX` и README `§2` (см. [DOCUMENTATION_MAP.md — протокол передачи](./DOCUMENTATION_MAP.md#agent-handoff-protocol)).
2. Статусы: **✅ готово** (критерий приёмки выполнен) · **🔄 в работе** · **🟡 частично** (фундамент есть, довести по ТЗ) · **⬜ не начато** · **♻️ переделать** (сделано, но не так, как требует ТЗ).
3. Текст требований сюда **не копировать** — только ID, статус, короткий указатель на код/handoff. Канон текста — само ТЗ.
4. Фаза стартует только после **плана в `docs/superpowers/plans/` и апрува владельца** (правило ТЗ «Арендная СДО» §13/§15 распространяется и на этот документ — см. раздел 12 ТЗ редизайна: фаза = один PR = один обратимый шаг, ≤30 файлов).
5. Расхождения «код ↔ ТЗ», найденные попутно, **записываются в раздел «Журнал расхождений»** этого файла — даже если исправлены в той же сессии. Молча починенное расхождение неотличимо от ненайденного.
