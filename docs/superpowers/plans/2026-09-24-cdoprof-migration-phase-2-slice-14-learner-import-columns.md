# Расширенный импорт слушателей (МГ-C3.1) — Фаза 2, срезы 10.1–10.2 — план

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax for tracking. План утверждён по поручению владельца (правила автономии ТЗ перехода).

**Goal:** ТЗ перехода §6.4 МГ-C3.1: массовый импорт с колонками отчество отдельно (или ФИО одной), дата рождения, пол, должность, телефон, паспорт (серия, номер, дата, кем выдан), гражданство, образование, компания (ИНН); лист «Как заполнять»; «Добавить слушателей списком» — в мастере группы (есть) и в реестре; частичный успех.

**Architecture:** Разведка (§5.592): импорт знает четыре колонки (ФИО, почта, СНИЛС, должность) + дата рождения; `createLearnerExtended` не принимает паспорт/пол/образование/компанию (в отличие от правки 8.12a); поиска компании по ИНН нет; вставка списком живёт только в мастере группы (`parseLearnerLines`, свой разбор на сервере `group-wizard-rows.ts`); реестр не ведёт на импорт вовсе. Два среза:

- **10.1 (бэкенд):** чистые нормализаторы колонок (`learner-import-fields.ts`: пол, дата, образование по коду/подписи ФРДО, ИНН, телефон, паспорт, ФИО из частей), `classifyRows` разбирает и валидирует новые колонки поимённо, `createLearnerExtended` принимает поля личного дела, `findCounterpartyByInn`; компания не найдена → строка принята с предупреждением; `groupId` необязателен — только заведение.
- **10.2 (фронт):** шаблон XLSX с новыми колонками и подсказками на листе «Как заполнять», синонимы заголовков в парсере, зеркало проверки, предпросмотр (≤7 колонок), предупреждения в итоге; в реестре — «Добавить слушателей списком» (панель с вставкой текста, без группы) и путь к загрузке файла; группа на экране импорта — необязательна.

**Tech Stack:** NestJS, class-validator, `lookup.seed.ts` (уровни ФРДО), `xlsx` на фронте, `WizardSteps`, `DetailDrawer`.

**Spec:** `TZ_TRUDSKILL_CDOPROF_MIGRATION.md` §6.4 МГ-C3.1, §4 поля слушателя; принцип частичного успеха (CLAUDE.md).

## Global Constraints

- Ручка та же (`POST learners/bulk-import`), поля запроса только добавляются, `groupId` становится необязательным (совместимость: старые клиенты шлют его всегда).
- Сторож `bulk-partial-success` — новых циклов по `request.*` не появляется.
- Колонок в предпросмотре ≤7; заголовки XLSX — по-русски.

## Решения (журнал РМ трекера)

- **РМ100.** Колонки принимаются «как написал человек» (пол «ж», дата «01.03.1990», образование подписью ФРДО), нормализует сервер; неразборчивое значение — отказ строки с текстом, что допустимо.
- **РМ101.** Компания по ИНН ищется среди контрагентов центра; не найдена — слушатель заводится **без компании с предупреждением** в строке итога (частичный успех), а не отказ и не автозаведение компании без реквизитов.
- **РМ102.** `groupId` необязателен: без группы импорт только заводит слушателей — этим же путём работает «Добавить слушателей списком» из реестра. Для строк «повторно использован» новые колонки не перезаписывают карточку (правка — через личное дело).

## Review Focus

1. Строка с датой «31.02.1990» или полом «да» — отказ поимённо, остальные строки приняты.
2. ФИО пусто, но заполнены фамилия и имя — строка принята; и то и другое пусто — отказ «ФИО».
3. ИНН незнакомой компании — строка принята, предупреждение видно в итоге.
4. Запрос без `groupId` — заведены, `enrolled = 0`, повтор с тем же ключом — тот же итог.
5. Старый файл с четырьмя колонками импортируется как раньше.
