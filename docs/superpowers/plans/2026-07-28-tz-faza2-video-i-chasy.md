> **Для агентов:** реализовывать по одной задаче за под-PR (`superpowers:executing-plans`). Фаза стартует только после **апрува владельца** (ТЗ §13, §15).

**Источник требований:** [`TZ_TRUDSKILL_ARENDNAYA_SDO.md`](../../../TZ_TRUDSKILL_ARENDNAYA_SDO.md) §4 (ЭПИК B) + ФТ-E1/E2 из §7. Статус — [`docs/TZ_ARENDNAYA_SDO_STATUS.md`](../../TZ_ARENDNAYA_SDO_STATUS.md).

- Готовый образец шва есть и обкатан: `WebinarProvider` (миграция `0055`) — per-tenant выбор провайдера, `noop` по умолчанию, реестр реализаций, настройки без секретов в БД. Копируем его целиком по форме.

Открытая вкладка = «пройдено», это и есть дыра ФТ-B3.
- SCORM-трекинг **уже доведён до общего прогресса** (`scorm.service.ts:425–445` вызывает `upsertMaterialProgress` по `lesson_status`), то есть ФТ-B4.2 в трекере занижен — проверяется и закрывается в Task 9 малой кровью.

## Архитектурные решения (зафиксировать на апруве)

1. **Шов `VideoProvider` — копия формы `WebinarProvider`** (`apps/backend/src/infrastructure/webinar-provider/webinar.provider.ts`): интерфейс + `noop` по умолчанию + `fake` для тестов + реестр `Map<code, provider>` + per-tenant резолвер по таблице настроек. Секреты провайдера — в секрет-хранилище, в БД только несекретная конфигурация (как `communication.webinar_provider_settings`).
2. **Видео — отдельная сущность `learning.video_assets`, а не поля в `materials`.** У одного видео свой жизненный цикл (загружается → обрабатывается → готово → ошибка), свой размер, длительность и идентификатор у провайдера; впихивать это в материал значит ломать таблицу при каждой смене провайдера. Материал ссылается на ассет, тип `'video'` в `Material.materialType` уже есть.
3. **Прогресс видео считается по позиции воспроизведения, а не по времени на странице.** Клиент шлёт heartbeat каждые 10–15 с с `positionSeconds` и множеством просмотренных отрезков; сервер — единственный, кто решает «пройдено». Нынешний `use-watch-tracker` для видео заменяется, для остальных типов материалов остаётся.
4. **Антиперемотка — серверное правило, а не UI-запрет.** Клиент прячет полосу перемотки, но зачёт даёт сервер: он не засчитывает отрезки, до которых слушатель «прыгнул». Иначе правило снимается через DevTools за минуту.
5. **Ссылки на видео — короткоживущие и привязанные к зачислению.** Presigned URL сегментов живёт минуты и выдаётся только слушателю с активным зачислением на курс, где лежит материал. Скачивание не запрещается технически (это невозможно), защита — водяной знак ФТ-B2.2 + короткие ссылки.
6. **Миграции только аддитивные** (ТЗ §13); URL и контракты `packages/api-contracts` не ломаем.
7. **Учёт часов опирается на `program.academic_hours`** (миграция `0030`, уже есть) — журнал сопоставляет фактическое время с плановыми часами программы.
