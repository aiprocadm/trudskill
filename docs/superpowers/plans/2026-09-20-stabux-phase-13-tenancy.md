# Фаза 13. Мультитенантность как товар

**ТЗ:** «Стабилизация, UX и развитие», фаза 13 (позиция 12 очереди выполнения).
**Дата:** 2026-09-20. **Предыдущая позиция:** 11 (фаза 16) — закрыта, PR #759–#763.

## Зачем фаза

Платформа сдаётся в аренду другим учебным центрам. Значит часть работы, которую сейчас делает
владелец руками, должна делать система: подключение центра, тариф и лимиты, своё оформление,
доказанная изоляция и видимый режим «Войти от имени».

**Порядок задан ТЗ:** 13.4 делается ПЕРВОЙ (приоритет P0, «утечка между центрами для арендной
модели фатальна»), и от неё же зависит поиск 3.6 — новый поиск по данным легко становится дырой.

## Срезы

### Срез 1 — 13.4: изоляция данных с доказательством

- [x] Поведенческий перебор: завести запись у центра Б, спросить из центра А, получить
      «не найдено». Не «запрещено»: «запрещено» подтверждает существование записи.
- [x] Обратная сторона: своя запись при этом читается (иначе «изолирован» и «мёртв» неразличимы).
- [x] Списки центра А не содержат записей центра Б, и счётчик тоже считает только свои.
- [x] Реестр сущностей сверяется с кодом: новый `getXxx(tenantId, id)`, забытый в переборе,
      роняет проверку. Это и есть «любая новая ручка проверяется на изоляцию».

### Срез 2 — 13.5: режим «Войти от имени» видим

- [x] Постоянная полоса сверху: от имени какого центра и под какой ролью идёт работа, и как выйти.
- [x] Необратимые действия в этом режиме требуют отдельного подтверждения с пометкой.
- [x] В журнале действий видно, что действие совершил администратор платформы.

### Срез 3 — 13.2: тариф, лимиты и потребление (Р12, Р13)

- [x] Расчёт активных слушателей месяца: уникальный человек, который начал обучение ИЛИ получил
      документ в расчётном месяце.
- [x] Мягкая блокировка: 80 % — предупреждение, 100 % — баннер, сверх лимита прекращается ТОЛЬКО

- [x] Никогда не прекращаются: доступ уже обучающихся, выдача документов по завершённому
      обучению, выгрузки в реестр.
- [x] Страница «Тариф и потребление» у администратора центра.

## Общие правила фазы

- Один срез = один PR = один обратимый шаг, ≤30 файлов.
- Каждый срез заканчивается зелёным `pnpm ci:check` (код выхода берётся из файла).
- Каждый сторож доказывается подсаженными поломками в обе стороны.
- Наборы прав — из живой `iam.role_permissions`, а не из названия роли.
