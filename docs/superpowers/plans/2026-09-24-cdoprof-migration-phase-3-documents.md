# Фаза 3 «документы» (МГ-F1–F5) — позиция 9, срезы 18.1–… — план

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax for tracking. План утверждён по поручению владельца (правила автономии ТЗ перехода).

**Goal:** ТЗ перехода §9 «Документы» [P0]: виды документов CDOPROF (МГ-F1.1), пакет документов группы (МГ-F2.1), нумерация CDOPROF и номера удостоверений (МГ-F3.1–F3.2), внешние документы (МГ-F4.1), предпросмотр и «что мешает выпустить» (МГ-F5.1).

**Architecture:** Разведка (§5.613): вида документа нет — модуль работает шаблонами и `documentType` (8 типов движка) и одним счётчиком на тип; привязки шаблонов, задачи и правила нумерации живут в снимке документов; из готового — закрытие группы (протокол + удостоверения, ZIP), приказы группы (без отрисовки), книга выдачи, проверки готовности трёх уровней; колонки `kind_code`, `series`, `rank`, `is_external` в `generated_documents` есть (0102, 0108), а сущность их не знает; номер уникален на весь центр — «номер приказа = код группы = номер протокола» столкнутся.

Срезы:

- **18.1 (F1.1 бэкенд):** каталог 14 видов (§9.1) в коде; `GET document-kinds`; `kindCode` у привязки шаблона, строки набора документов курса, задачи и документа; выпуск по набору несёт вид.
- **18.2 (F1.1 фронт):** справочник видов на экране документов, вид в строке набора документов курса и в привязке шаблона.
- **19.x (F3.1):** нумерация CDOPROF — токены `{group.code}`, `{protocol.number}`, `{seq.group}`, `{seq.year}`, `{series}`, политики, три части номера, счётчики по виду и области; уникальность номера — в пределах вида (миграция, ослабляющая ограничение); предпросмотр следующего номера на сервере; сброс счётчика с подтверждением и аудитом.
- **20.x (F5.1, F3.2):** готовность «что мешает выпустить» одной ручкой (центр, экзамен, слушатель + дата рождения, должность, согласие — настройкой); предпросмотр на реальных данных без номера с пометкой «ОБРАЗЕЦ»; серия и разряд у удостоверения, «Номера удостоверений» группы.
- **21.x (F2.1):** пакет документов группы — вкладка «Документы» группы (виды набора × состояние), мастер «Сформировать пакет» (даты, причина, комиссия, преподаватель, начальный номер), выпуск приказ → протокол → удостоверения, статус группы «документы» → «закрыта», повтор — перевыпуск, а не дубли.
- **22.x (F4.1):** внешние документы — сущность, ручное заведение и скан, запрет перевыпуска, книга выдачи с отбором по слушателю, группе и виду.

## Решения (журнал РМ трекера)

- **РМ123.** Виды документов — каталогом в коде (14 системных видов §9.1), без таблицы: в MVP центр не заводит своих видов; «вид» — строка у привязки, строки набора, задачи и документа; вид обязан подходить шаблону по типу движка.
- **РМ124.** Решения, которые ТЗ оставило владельцу, принимаются по умолчанию (владелец может поменять настройкой): у пяти видов приказов — общий счётчик центра; серия удостоверения — свободная строка курса/группы (пусто по умолчанию); разряд — у слушателя в «Номерах удостоверений»; «требовать согласие на ПДн перед выпуском» — выключено по умолчанию; начальные значения счётчиков — вручную до переноса (Фаза 4, О1/О2).
- **РМ125.** Номер уникален в пределах вида правила: проверка в памяти — «вид + номер», заявка в базе — «вид␟номер» в прежней таблице 0088, индекс выпущенных документов 0117 ослаблен до `(центр, вид, номер)`; номера без вида — как раньше.
- **РМ126.** Политики CDOPROF — готовые шаблоны из токенов, без поля `policy`; три части номера — `parts` правила (старт + «растёт сама»).
- **РМ127.** Перевыпуск документа с номером из данных группы — с тем же номером в 21.x; до того понятный отказ.

## Review Focus

1. Выпуск по набору курса без вида — как раньше (вид необязателен).
2. Удостоверение на шаблоне приказа — отказ с названием шаблона и вида.
3. Документ, выпущенный по строке набора с видом, в книге выдачи и проекции несёт вид (`kind_code`).
4. Номер приказа = код группы у двух групп с одинаковым кодом — невозможно (код группы уникален), у протокола и приказа одной группы — разрешено после 19.x.
5. Повторное «Сформировать пакет» не создаёт вторых номеров.

## Task 3: срез 19.1 — номер уникален в пределах вида документа, правило нумерации по виду

**Зачем.** Политики CDOPROF «номер приказа = код группы» и «номер протокола = код группы» дают двум документам разных видов один и тот же номер. Сегодня это запрещено трижды:

- проверкой в памяти (`document_number_taken`);
- заявкой номера в базе (`issued_number_claims`, ключ «центр + номер»);
- индексом выпущенных документов (`generated_documents_tenant_number_uniq`).

Внутри вида дубль по-прежнему запрещён.

**Files:**

- `documents/documents.service.ts`: `reserveNumber(tenantId, documentType, kindCode?)`. Правило вида ищется раньше правила типа. Ключ проверки — вид + номер. Вызовы передают `task.kindCode`.
- `documents/documents.types.ts`: `kindCode?` у правила и у резервирования.
- `documents/documents.request-dto.ts`, `documents.dto.ts`: `kindCode?` при создании правила. Вид обязан подходить типу.
- `documents/infrastructure/issued-number-claims.ts`: ключ заявки — `вид␟номер` для документов с видом. Документы без вида заявляются как раньше.
- `postgres-documents-persistence.backend.ts`: передаёт вид в заявку.
- `migrations/0117_generated_documents_number_per_kind.sql`: индекс `(tenant_id, coalesce(kind_code, ''), document_number)` вместо `(tenant_id, document_number)`. Ограничение ослабляется, данные не трогаются. Прежний индекс снимается.
- Тесты: `documents.numbering-kinds.test.ts`, дополнение `issued-number-claims.integration.test.ts`, тест миграции.

**Tasks:**

- [x] Правило нумерации с видом. Создание правила вида выключает только прежнее правило того же вида.
- [x] `reserveNumber` с видом. Один номер у двух видов разрешён, дубль внутри вида даёт `document_number_taken`.
- [x] Заявка номера по виду и миграция 0117. Сторож `uniqueness-backed-by-db` остаётся зелёным.
- [x] Документация §5.615, `pnpm ci:check`, PR, слияние.
