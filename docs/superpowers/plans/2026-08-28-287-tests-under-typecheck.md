# Программа 287 — тесты бэкенда под проверкой типов

**Дата:** 2026-08-28. **Журнал расхождений:** запись 287 (слепая зона).
**ТЗ:** аренда (качество кода; сторожевой контур).

## Зачем

`apps/backend/tsconfig.json` исключает `src/**/*.test.ts`, поэтому проверка типов не видит
тесты. Класс промаха «конструктор класса вырос на аргумент, а вызов в тесте не обновлён»
ловится только прогоном, и если промах уезжает в `setImmediate`, прогон краснеет
`Unhandled Errors`, **не называя виновный тест**. На этом обжигались дважды
(`enrollment-certificate-flow.service.test.ts` с `auditService`, порция 26 с четвёртым
аргументом). Фронтенд свои тесты типами проверяет — бэкенд и `packages/ui` нет.

## Границы

- **Боевой код не подгоняем под тесты.** Если тест зовёт сервис не так, как тот объявлен, —
  правится тест. Обратное (правка боевого кода ради зелёного теста) допустимо только когда
  найден настоящий дефект, и тогда он идёт в журнал отдельной записью.
- **Строгость не ослабляем**: никаких `any`, `@ts-expect-error` без объяснения, отключения
  правил в `tsconfig`. Разрешено `as unknown as X` для заглушек с комментарием почему.
- Недостающая зависимость в конструкторе — подставляем настоящую заглушку, а не `undefined!`.

## Приёмка

1. `npx tsc -p apps/backend/tsconfig.test.json --noEmit` — exit 0.
2. `pnpm ci:check` — exit 0 (смотреть код выхода, а не строку «Tests N passed»).
3. Сторож падает на возврате исключения тестов в `apps/backend/tsconfig.json` — проверено
   подсадным нарушителем.
4. Прогон бэкенда не потерял тестов: число тестов до и после совпадает.
