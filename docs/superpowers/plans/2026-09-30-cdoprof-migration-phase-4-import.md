# Фаза 4 «импорт из CDOPROF» (МГ-K1–K6, МГ-M1) — позиция 10 — план

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax for tracking. План утверждён по поручению владельца (правила автономии ТЗ перехода).

**Goal:** ТЗ перехода §13.4 «Импорт» [P0]: модуль `import-cdoprof` — источники (API, XLSX), нормализаторы и проверки, дедупликация с кандидатами на слияние, загрузчики по доменам в порядке контрагенты → направления → курсы → слушатели → группы → курсы групп → зачисления → документы; сухой прогон, отчёт строк, повтор только ошибок, идемпотентность по внешним ID (МГ-K2.1); экран импорта; файлы документов (МГ-K6.1); сверка ЕИСОТ/ФРДО (МГ-M1).

**Architecture:** Разведка (субагент, 30.09): модуль `apps/backend/src/modules/import-cdoprof/` уже содержит клиент API CDOPROF (`sources/cdoprof-api-client.ts`) с транспортами HTTP и фикстур (`__fixtures__/cdoprof-api/dataset.json`), схемы ответов и проверку ИНН, но в приложение не подключён. Таблицы `migration.legacy_ids`, `import_runs`, `import_rows` есть (0100); действие строки — `created | updated | skipped | failed`. Нормализаторы СНИЛС, ФИО, телефона, дат — в модуле групп и слушателей. Колонки XLSX-выгрузок неизвестны до О2; живой прогон ждёт ключ API (О1) и стенд (О5).

**Ограничения живой части:** ключ API CDOPROF (О1), выгрузки (О2), стенд и ответственный по 152-ФЗ (О5) — у владельца. Всё ниже строится и проверяется на синтетических данных; живой прогон — 🚫 до входов владельца.

Срезы:

- **23.2 (K3.1, K2.1):** боевой прогон контрагентов и слушателей — создание и обновление через сервисы модуля групп, `legacy_ids`, повтор даёт 0 новых, «повторить только ошибки».
- **23.3 (K3.1):** направления, курсы, группы, курсы групп, зачисления — тем же ходом.
- **23.4 (K3.1):** XLSX-источники по §13.2 (синтетические выгрузки до О2).
- **23.5:** экран импорта в настройках: запуск, сухой прогон, отчёт строк, кандидаты на слияние, повтор ошибок.
- **23.6 (K6.1, M1):** файлы документов по номеру и слушателю; сверка ЕИСОТ/ФРДО на эталонах.

## Решения (журнал РМ трекера)

- **РМ132.** Сухой прогон 23.1 идёт синхронно в запросе и ничего не меняет в данных центра: он читает снимок, сопоставляет и пишет только запуск и строки импорта. Фоновая задача `import_cdoprof` — вместе с боевым прогоном (23.2), где объёмы 13 755 слушателей требуют очереди.
- **РМ134.** Ключ API CDOPROF — в окружении стенда с явной привязкой к центру (`CDOPROF_IMPORT_TENANT_ID`): ключ одного центра не отдаётся администратору другого центра того же стенда.
- **РМ133.** «Кандидат на слияние» — строка со статусом `skipped` и кодом `merge_candidate` (таблица 0100 знает только четыре действия): совпадение по ФИО+дате рождения без внешнего ID и СНИЛС не сливается автоматически, а ждёт человека (ТЗ §18: «автослияние — ошибка»).

## Review Focus

1. Сухой прогон не создаёт ни одного слушателя и контрагента (сравнить снимок до и после).
2. Слушатель с тем же СНИЛС, что у существующего, — сопоставление, а не новый; с тем же ФИО и датой рождения без СНИЛС — кандидат на слияние.
3. Неверный СНИЛС или ИНН — строка `failed` с причиной, остальные строки идут дальше (частичный успех).
4. Запуск доступен только с правом `import.run`; у других ролей ручек нет.
5. `raw` строки не хранит ПДн открыто (маскирование).
