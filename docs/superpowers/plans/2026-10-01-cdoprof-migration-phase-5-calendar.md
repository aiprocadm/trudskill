# Фаза 5 «календарь и уведомления» (МГ-G1, G3, I1, I3, L4, L5) — позиция 11 — план

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax for tracking. План утверждён по поручению владельца (правила автономии ТЗ перехода).

**Goal:** ТЗ перехода §5 «Календарь и расписание» и §13 «Уведомления»:

- агрегатор событий `GET /calendar/events` (МГ-G1.1, G3.3);
- экран `/calendar` с видами день / неделя / месяц / список (МГ-G3.1, G3.4, G3.5);
- замена «Календаря окончаний»;
- перенос экзамена с уведомлением (МГ-G1.1);
- уведомления задач и экзаменов (РМ26), личные каналы уведомлений (МГ-I1.1, I3.1);
- панель куратора `/curator` (МГ-L4.1), вкладка «История» (МГ-L5.1).

**Architecture:** Разведка (субагент, 01.10) показала:

- События не хранятся: `calendar.events` — запрос по источникам (ТЗ §5.4.4). Нужные индексы по датам есть (0101, 0104, 0107).
- Задачи отдаёт `TasksService` (экспортирован, права «свои / все» уже в нём).
- Даты групп, курсы групп и зачисления лежат в снимке центра.
- «Календарь окончаний» (`/learning/calendar`, `features/learning-calendar`) читает `GET /enrollments` по `planned_end`.
- Уведомления идут через `NotificationDispatcher` (каталог, `dedupKey` — «ровно один раз»); личных настроек каналов нет.

**Срезы:**

- **24.1 (МГ-G1.1, G3.3 — сервер):** право `calendar.read` (0120, РМ21 — вместе с ручкой); `modules/calendar`.
  - `GET /calendar/events?from&to&types&mine&groupStatus&counterpartyId&directionId&q`, период ≤ 93 дней → 400 `range_too_wide`.
  - События групп (начало, окончание, экзамен, окно экзамена, конец доступа к материалам, практика), окончания обучения (по группе и дню), задачи.
  - Каждый тип — только при праве чтения его источника.
  - Замер: неделя на синтетике 25 000 групп ≤ 500 мс.
- **24.2 (МГ-G3.1, G3.4, G3.5 — экран):** `/calendar`: неделя / месяц / список (на 360 px — список), фильтры ≤ 3, быстрая карточка, «Сегодня»; вид в URL.
- **24.3:** замена «Календаря окончаний» (РМ по слушателю: у него нет `calendar.read`).
- **24.4 (МГ-G1.1):** перенос экзамена в календаре с подтверждением → аудит `learning.group_exam_moved` → уведомление `exam_moved`; `calendar.manage`.
- **24.5 (РМ26, МГ-I3.1):** уведомления задач (`task_assigned`, `task_done`, `task_returned`, `task_due_soon` — ровно один раз).
- **24.6 (МГ-I1.1):** личные каналы уведомлений `PATCH /me/notification-settings`.
- **24.7 (МГ-L4.1):** `/curator`.
- **24.8 (МГ-L5.1):** вкладка «История».

## Решения (журнал РМ трекера)

- **РМ138.** Кто видит календарь: `calendar.read` у администрации центра и платформы, руководителя, куратора и преподавателя (матрица ТЗ §12 «Календарь: события»); методисту — нет, в матрице его нет.
  - Тип события показывается, только если у человека есть право читать его источник: группы — `groups.read`, окончания — `enrollments.read`, задачи — `tasks.read`. Задачи — по правилам задач («свои», все — с `tasks.manage_all`).
  - «Мои»: группы, где человек ответственный или преподаватель курса, и его задачи. Жёсткого сужения по роли нет — оно было бы новым правом, которого ТЗ не вводит. По умолчанию «мои» для куратора и преподавателя включает экран.
- **РМ139.** Источник данных 24.1 — снимок центра (как у реестра групп при выключенном `LMS_NORMALIZED_COLLECTIONS`). Путь через нормализованные таблицы с индексами по датам — с включением флага на стенде; замер «неделя ≤ 500 мс» делается и там.
- **РМ140.** «Окончание обучения» — одно событие на группу и день («Окончание обучения · 264501 · 12 слушателей»), а не на каждого слушателя: 13 755 слушателей превратили бы месяц в сплошной список. Список слушателей — в карточке события.

## Review Focus

1. Период больше 93 дней и «до» раньше «с» — 400 словами, а не пустой ответ.
2. Без `enrollments.read` окончаний нет; без `tasks.read` задач нет; чужие задачи — только с `tasks.manage_all`.
3. Событие, начавшееся до периода и закончившееся в нём (окно экзамена, практика), попадает в календарь.
4. «Мои» не показывает чужую группу, даже если в ней экзамен.
5. Изоляция: события другого центра не видны.
