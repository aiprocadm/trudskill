## 1. Резюме и цели

### 1.1. Что не так сейчас — языком пользователя

**«Тяжело воспринимается».** Администратор после входа видит боковое меню, в котором **70 пунктов в 10 раскрывающихся блоках** — все одновременно, потому что у роли `tenant_admin` в базе выданы **все** права без исключения (`apps/backend/migrations/0010_iam_role_permissions_and_seed.sql:98–108` — `join iam.permissions p on true`, фильтра для этой роли нет). Ни один пункт не скрыт. Меню не помогает выбрать — оно предлагает выбрать из семидесяти.

**«Нарушена логика разделов».** Один и тот же объект живёт по двум адресам: слушатели — `/learners` и `/admin/learners`, курсы — `/courses` и `/learner/courses`, документы — `/documents` и `/learner/documents`. У администратора **две стартовые панели**: `/workspace` (183 строки, живые данные) и `/admin/cockpit` (7 строк, сетка виджетов) — обе в блоке «Обзор», при этом вход ведёт только на первую (`apps/frontend/src/features/navigation/role-home.ts:47`).

**«Цвета мешают».** На стартовом экране администратора `/workspace` пять смысловых блоков подряд, три таблицы, две выпадашки вне панели фильтров, а колонка «Маршрут» показывает пользователю сырой URL вида `/admin/tests` как данные. Единственное первичное действие в шапке — кнопка «Обновить», то есть перезагрузка, а не работа.

**«Не видно, что делать дальше».** Механизм для этого написан: `/workspace` уже возвращает `overdueCount`, `blockersCount`, `nextActions` (`apps/frontend/src/features/workspace/types.ts`). Но выводится он как строка `Просрочено: 0` внутри `ui-inline`, хотя в дизайн-системе есть готовый `StatCard`.

## 4. Новая информационная архитектура

Главный раздел. Здесь решается конфликт «мало ссылок» против «30 админских разделов».

### 4.1. Ограничение, из которого всё следует

`apps/frontend/src/e2e/ia-architecture.e2e.test.ts` держит инвариант:

> каждый маршрут принадлежит **ровно одному** блоку ИА, объявлен служебным или скрытой заглушкой

Блоки ИА — это **полное разбиение** пространства из 102 маршрутов. Маршрут без блока = сирота (тест красный), маршрут в двух блоках = ошибка (тест красный).

**Следствие:** меню из ≤7 пунктов физически не может заменить 10 блоков. Если сократить блоки, придётся переназначить маршруты всех схлопнутых.

### 4.2. Решение: два слоя вместо одного

`ID: IA-010.` Информационная архитектура разделяется на два независимых слоя.

| Слой          | Что это                                  | Размер                 | Кто отвечает                                                    |
| ------------- | ---------------------------------------- | ---------------------- | --------------------------------------------------------------- |
| **Разбиение** | 10 блоков ИА, покрывают все 102 маршрута | 10 блоков / 70 пунктов | `nav-groups.ts`, охраняется `ia-architecture.e2e.test.ts`       |
| **Видимость** | Что администратор видит в меню сразу     | **≤ 7 пунктов**        | `helpers.ts:getNavigationView`, `role-blueprints.ts:primaryNav` |

Разбиение остаётся полным и неизменным. Меняется только то, что показывается сразу. Это ровно та модель, которую реализует уже написанная `getNavigationView`: `{ main: ≤7, more: [...] }`, где `more` не теряется, а уезжает во второй уровень.

**Решение по числу блоков:** ⚠️ **оставляем 10.** Сокращение до 7 потребовало бы переназначить маршруты трёх блоков и переписать сторожа, при нулевой пользе для пользователя — он блоков в новом меню и так не увидит, они станут структурой второго уровня.

### 4.3. Решение по находке 2: подключаем `getNavigationView`

`ID: IA-011.` `app-shell.tsx` переводится с `getGroupedNavigation` на `getNavigationView`.

Обоснование — работа уже сделана и лежит без применения:

| Слой данных                          | Файл                   | Состояние                                                                                          |
| ------------------------------------ | ---------------------- | -------------------------------------------------------------------------------------------------- |
| Разметка «основное / второстепенное» | `model.ts`             | **54 из 70** пунктов помечены `navSlot: 'more'` вручную                                            |
| Сокращённые меню по ролям            | `role-blueprints.ts`   | `primaryNav` у всех 5 ролей, по 5–6 пунктов — **уже в бюджете ≤7**                                 |
| Сборщик                              | `helpers.ts:29`        | `getNavigationView` написана и покрыта тестом                                                      |
| Отображение роли                     | `app-shell.tsx:32,138` | `getPrimaryRoleBlueprint` **вызывается**, но результат идёт только в надпись «Роль: Администратор» |

### 5.2. ⚠️ Брендирование тенанта ломает гарантию контраста

`features/branding/theme.ts:brandingToThemeVars` перекрывает ровно пять переменных: `--ui-brand-600`, `--ui-brand-700`, `--ui-surface-accent`, `--ui-accent-600`, `--ui-accent-700`.

**`--ui-on-accent` в список не входит.** Значит текст на первичной кнопке остаётся тёмным (`#0f172a`) при любом цвете арендатора. Логика «коралл светлый, поэтому текст тёмный» верна для коралла и **неверна для произвольного цвета**: арендатор с тёмно-синим акцентом получит тёмный текст на тёмном фоне.

`ID: UI-005.` ⚠️ `brandingToThemeVars` вычисляет `--ui-on-accent` от выбранного цвета: относительная яркость по WCAG, порог 0.5 → `#0f172a` или `#ffffff`. Функция чистая, покрывается юнит-тестом на граничные значения (тёмно-синий, ярко-жёлтый, средне-серый). То же для `--ui-brand-*`, если на бренд-цвете рисуется текст.

`ID: UI-006.` `--ui-nav-sidebar-bg` и остальные `--ui-nav-*` **не** отдаются арендатору: сайдбар — тёмная поверхность с гарантированным контрастом, произвольный цвет там непредсказуем. Фирменный цвет арендатора проявляется в логотипе, активном пункте и первичных кнопках. Решение фиксируется письменно, чтобы следующий агент не «дочинил» это как недоделку.

Существует (`dialogs/index.tsx:112`), используется в 3 местах против 9 вызовов `window.confirm()`.

```ts
tone?: 'default' | 'danger';        // danger → кнопка --ui-danger-600
requireTyping?: string;             // для необратимых: ввести название объекта
```

**Состояния:** обычное, опасное, подтверждение выполняется (кнопка в загрузке, диалог не закрывается).
**Доступность:** фокус на кнопке отмены при открытии, ловушка фокуса, `Esc` = отмена.

#### `CMP-006` · Замена `window.confirm()`

`ID: CMP-006.` Все 9 вызовов заменяются на `ConfirmDialog`. `window.confirm` блокирует поток, не стилизуется, не переводится и не проходит проверку на 360px.

### 6.3. Создать

#### `CMP-010` · `DetailDrawer` — боковая панель деталей

**Приоритет: наивысший.** В приложении **пять независимых реализаций** этого компонента:

```
features/learners/learner-edit-drawer.tsx
features/clients/client-edit-drawer.tsx
features/assessment-admin/question-editor-drawer.tsx
features/assessment-admin/assignment-edit-drawer.tsx
features/assessment-admin/question-bank-edit-drawer.tsx
```

плюс три модалки того же назначения: `group-orders/issue-order-modal.tsx`, `issuance-journal/revoke-reissue-modal.tsx`, `recertification/approve-recert-modal.tsx`. Компонент не «создаётся с нуля» — он **объединяет восемь существующих**.

**Назначение:** посмотреть и отредактировать объект, не уходя с реестра. Прямо служит бюджету «≤3 клика».

```ts
open: boolean;
onClose: () => void;
title: string;
subtitle?: string;
width?: 'sm' | 'md' | 'lg';        // 420 / 560 / 720 px
footer?: ReactNode;                 // до 1 первичного действия
isLoading?: boolean;
error?: unknown;
onRetry?: () => void;
```

**Состояния:** закрыт, открывается, загрузка (скелет), данные, ошибка с повтором, сохранение, есть несохранённые изменения (подтверждение при закрытии).
**Мобильное (≤480px):** разворачивается на весь экран, шапка липкая, футер липкий.
**Доступность:** ловушка фокуса, `Esc` = закрыть, `aria-modal`, возврат фокуса на строку, из которой открыт. Фон страницы получает `aria-hidden`.

#### `CMP-011` · `BulkActionBar` — массовые действия

**Назначение:** появляется при выделении строк.

```ts
selectedCount: number;
actions: Array<{ label: string; onSelect: () => void; danger?: boolean; disabled?: boolean }>;
onClear: () => void;
```

**Анатомия:** липкая полоса внизу списка: «Выделено: 12» → действия → «Снять выделение».
**Состояния:** скрыта (0 выделено), видна, действие выполняется, частичный успех (12 из 15 — с поимённым списком отказов).
⚠️ Частичный успех — обязательное состояние, не опциональное: в системе уже есть прецедент поимённого отсева при закрытии группы.

#### `CMP-012` · `SavedViews` — сохранённые представления

**Назначение:** админ возвращается к одним и тем же срезам («не сдали», «ждут документа»).

```ts
views: Array<{ id: string; label: string; query: Record<string, string> }>;
activeId?: string;
onApply: (id: string) => void;
onSave: (label: string) => void;
onDelete: (id: string) => void;
```

**Умолчание вместо настройки:** каждый реестр получает 2–3 предустановленных представления из коробки. Пустой список «сохранённых» бесполезен.
⚠️ Хранение: `localStorage` — префикс ключа согласуется с разделом 11-B. Серверное хранение — **вне границ этого ТЗ** (потребовало бы изменения контракта API, см. раздел 14).

#### `CMP-013` · `AttentionWidget` — «требует внимания»

**Назначение:** блок «Разобрать» на `/workspace` (`IA-016`).

```ts
items: Array<{
  id: string; title: string; href: string;
  severity: 'high' | 'medium' | 'low';
  dueAt?: string;
  action?: { label: string; onSelect: () => void };
}>;
maxVisible?: number;      // по умолчанию 7
emptyState: { message: string; hint?: string };
```

**Состояния:** загрузка, есть элементы, пусто («Всё разобрано» — не «нет данных»), ошибка.
**Правило:** элементы отсортированы по срочности, не по типу. Пользователю нужна очередь, а не оглавление.

#### `CMP-014` · `EmptyState` с действием

Существующий `EmptyState` принимает `message` и `hint`. Нужно третье:

```ts
action?: { label: string; href?: string; onSelect?: () => void };
```

`ID: CMP-014.` Пустое состояние объясняет, **что это за раздел и что сделать первым**. Формулировка «Нет данных» запрещена — см. раздел 9.

#### `CMP-015` · `PageShell` — шапка и контейнер страницы

Переезд `PageContainer` / `PageHeader` / `SectionCard` из приложения в пакет (см. 6.4).

```ts
// PageHeader
title: string;
subtitle?: string;
primaryAction?: { label: string; onSelect: () => void };   // ровно один, UI-007
secondaryActions?: Array<{ label: string; onSelect: () => void }>;  // в меню «…»
breadcrumbsSlot?: ReactNode;
```

⚠️ Тип `primaryAction` — **не массив**. Бюджет «1 первичное действие» становится ограничением типа, а не договорённостью, которую забудут.
