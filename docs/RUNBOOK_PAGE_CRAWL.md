# Обход страниц браузером

Проверка «каждая страница открывается и не падает» — под каждой ролью. Инструмент:
[`scripts/crawl/pages-smoke.mjs`](../scripts/crawl/pages-smoke.mjs).

## Зачем это нужно

Экраны рисуются в браузере. Ни тесты (в наборе нет ни браузера, ни монтирования компонентов —
`RISK-002`), ни ответы сервера падения отрисовки не показывают. Дважды это доходило до
владельца раньше, чем до нас:

| Что видел человек                                           | Что было на самом деле                                                 | Журнал |
| ----------------------------------------------------------- | ---------------------------------------------------------------------- | ------ |
| Красный экран «map is not a function» вместо карточки курса | тип фронта объявлял массив, сервер отдавал `{ items }`                 | 379    |
| «Verify failed: HTTP 500» на публичной проверке документа   | журнал писался от несуществующего центра, внешний ключ отклонял запись | 380    |

Оба раза сервер был здоров, его журналы чисты, тесты зелёные — а страница сломана.

## Подготовка (один раз)

### 1. Браузер

Нужен chromium. `sudo` на сервере под паролем, поэтому ставится **без прав администратора**:

```bash
cd /tmp && mkdir -p chromedeps && cd chromedeps
apt-get download libasound2t64 libatk1.0-0t64 libatk-bridge2.0-0t64 libatspi2.0-0t64 \
  libcairo2 libcups2t64 libpango-1.0-0 libxdamage1 \
  libavahi-client3 libavahi-common3 libharfbuzz0b libpixman-1-0 libthai0 libxcb-render0 \
  libdatrie1 libgraphite2-3
for f in *.deb; do dpkg -x "$f" ~/.local/chromedeps; done
```

Перед запуском:

```bash
export LD_LIBRARY_PATH=$(find ~/.local/chromedeps -name '*.so*' -printf '%h\n' | sort -u | tr '\n' ':')
```

Сам бинарник берётся из кэша playwright соседних проектов
(`~/.cache/ms-playwright/chromium-*/chrome-linux64/chrome`); путь переопределяется флагом
`--chrome`.

### 2. Витрина, собранная под «одну дверь»

⚠️ **Главная тонкость.** В песочнице разработки браузер видит НЕ ВСЕ локальные порты: витрину
на 3210 видит, сервер на 3011 — нет. Поэтому скрипт поднимает «одну дверь» (прокси на 3211):
`/api` и `/realtime` уходят на сервер, остальное — на витрину. Браузер ходит только в неё —
заодно исчезает запрет чужого источника.

Адрес сервера зашивается в витрину **на сборке**, поэтому собирать надо с адресом двери:

```bash
cd apps/frontend
NEXT_PUBLIC_API_BASE_URL=http://127.0.0.1:3211/api/v1 \
NEXT_PUBLIC_REALTIME_URL=ws://127.0.0.1:3211/realtime \
pnpm exec next build --webpack

# автономный сервер сам не раздаёт статику — её кладут рядом
cp -r .next/static .next/standalone/apps/frontend/.next/
cp -r public .next/standalone/apps/frontend/

PORT=3210 node .next/standalone/apps/frontend/server.js &
```

Порт 3210 — не догма, но **3000 занят стендом другого проекта**, туда лезть нельзя.

## Запуск

```bash
node scripts/crawl/pages-smoke.mjs --roles tenant_admin,manager,methodist,learner,platform_admin
```

Полезные флаги: `--app`, `--api`, `--door`, `--tenant`, `--password`, `--wait`, `--chrome`.

⚠️ **`--door` обязан совпадать с портом, под который собрана витрина.** Иначе страницы
откроются, но сессия не поднимется: витрина будет звать сервер по одному адресу, а браузер
ходить по другому. Проверка это ловит («обход недействителен»), но час на разбор экономит
именно эта строка — на ней уже споткнулись при написании инструмента.

Код возврата: `0` — чисто, `1` — есть о чём разбираться.

## Как читать вывод

- `✗ /адрес` с текстом ошибки — падение отрисовки. Разбираться обязательно.
- `⚠ НИ ОДНА страница не показала роль` — **обход недействителен**: сессия не поднялась, и
  «ошибок нет» не значит ничего. Так уже было дважды; обычная причина — витрина собрана не с
  адресом двери.
- Экраны «403 недостаточно прав» и «ссылка для входа недействительна» — это ПРАВИЛЬНОЕ
  поведение, а не находки.

## Чего обход НЕ покрывает

- **Действия.** Он открывает страницы, но не нажимает кнопки: клик может что-нибудь удалить
  или выпустить документ. Ошибки, возникающие при отправке форм, сюда не попадают.
- **Другой учебный центр.** Витрина собирается с центром по умолчанию, поэтому под учётной
  записью ЧУЖОГО центра сессия не поднимается — проверка честно скажет «обход недействителен».
  Путь «запись другого центра» закрыт иначе: состоянием `RecordNotFound` и его сторожем
  (`detail-screen-handles-missing`).

## Границы

Это дымовая проверка «открывается и не падает». Она не проверяет вёрстку, смысл текстов и
права — для прав есть свои сторожа (`controllers-tenant-scope`, `permission-surface`), для
текстов свои (`latin-titles-ban`, `empty-states-explain`).

Скрипт **не входит** в `pnpm ci:check`: ему нужны поднятая витрина, живой сервер и браузер вне
репозитория. Это ручная проверка после заметных правок и перед показом владельцу.
